# Design

## Context

В текущем конфиге `lua/autostart.lua` открывает nvim-tree на `VimEnter`, `lua/settings/neogit.lua` задаёт `kind = "tab"`, а `lua/hotkeys.lua` привязывает Option+F к `NvimTreeFocus` и Option+G к `wincmd l`. Целевая среда проверена на Neovim 0.12.6, nvim-tree `ba85443` и Neogit 3.0.0. Причина изменения описана в [proposal.md](proposal.md).

## Goals / Non-Goals

- Изолировать управление левой панелью в одном Lua-модуле и опираться на публичные API плагинов.
- Сохранить штатные команды плагинов, пользовательские команды, `vim.pack` и Noirbuddy. Закреплённые версии зависимостей остаются прежними.
- Область интеграции охватывает дерево и основной Git-статус. Неограниченные по ширине окна коммитов, diff и всплывающие меню остаются под управлением Neogit.

## Decisions

### Две панели в одной странице Neovim

```text
+--------------------+----------------------------------+
| Explorer | Git     | init.lua | hotkeys.lua [+]        |
+--------------------+----------------------------------+
| Active tool        | Editor and splits                |
+--------------------+----------------------------------+
```

Модуль раскладки хранит выбранную вкладку, левое окно и последнее подходящее окно редактора для текущей страницы Neovim. При открытии и закрытии панелей модуль проверяет актуальность идентификаторов окон. Использование отдельной страницы для каждого инструмента потребовало бы синхронизировать правые окна между страницами.

Explorer открывается через публичный `nvim-tree.api.tree.open({ winid = … })`. При выходе из Explorer модуль использует публичное закрытие дерева в текущей странице, чтобы nvim-tree учитывал жизненный цикл окна. Для Git модуль выделяет левый сплит и вызывает `require("neogit").open({ kind = "replace", cwd = … })` из этого сплита. Альтернативный `vsplit_left` отдаёт создание окна Neogit и оставляет меньше контроля над его шириной. Модуль проверяет рабочий каталог до вызова Neogit, поскольку штатное открытие вне рабочего дерева может предложить создать репозиторий.

Переключение меняет только левый сплит. При его пересоздании сохраняется ширина панели, а для правых окон проверяется сохранение обзора. Статус открывается от рабочего каталога редактора, выбранного до перехода в левое окно. Стандартный `:Neogit` сохраняет настройку `kind = "tab"` для самостоятельного открытия, когда статус ещё не виден. Если Neogit фокусирует уже открытый статус того же репозитория, модуль проверяет фактическое окно и восстанавливает пригодную для работы боковую панель. Видимое окно за пределами панели остаётся доступным.

### Две полосы вкладок через `winbar`

Полосы используют оконный `winbar` и формат `%@…@` для кликов. Обработчики различают левую кнопку, проверяют целевое окно и направляют файловый клик в редактор. Если справа несколько сплитов, переключение файлов относится к окну, которому принадлежит нажатая полоса. Если файл уже открыт именно в этом окне, достаточно вернуть туда фокус. Метка активного файла определяется по буферу окна редактора, поэтому сохраняется при фокусе слева. Цвета задаются через стандартные группы выделения Neovim, доступные в Noirbuddy.

Установленный mini.tabline 0.18.0 отсутствует в `vim.pack` и текущей настройке. Его публичный рендерер рассчитан на глобальный `tabline`, а встроенный обработчик выбирает буфер в текущем окне. Оконная полоса даёт нужную ширину и явную цель клика. Дополнительная зависимость не требуется.

## Risks / Trade-offs

- Neogit сам управляет временем жизни статусного буфера. После закрытия или вытеснения статуса модуль заново проверяет окно и при необходимости открывает статус через публичный API. Сохранение внутренней позиции Neogit между переключениями зависит от плагина.
- При выборе другого файла в правом окне изменённый буфер остаётся загруженным. Для этого операция смены буфера должна корректно работать и при отключённом `hidden`, без принудительного удаления или сохранения.
- Узкий терминал ограничивает число вкладок, помещающихся в `winbar`. Полоса должна сохранять доступ к текущему файлу и отличать модифицированные и одноимённые файлы при наличии места. Клавиатурная навигация по буферам остаётся доступна.

## Migration Plan

При следующем запуске новая раскладка инициализируется вместо прямого открытия дерева. Форматы данных и lock-файл не требуют миграции. Для отката достаточно вернуть прежние точки входа панели и её горячие клавиши.
